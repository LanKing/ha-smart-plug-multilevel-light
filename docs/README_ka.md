1. გახსენით**მთავარი ასისტენტი → Zigbee2MQTT**. თუ Zigbee2MQTT არ არის გვერდით მენიუში, გახსენით**პარამეტრები → აპლიკაციები → Zigbee2MQTT → გახსენით ვებ ინტერფეისი**.

3. აირჩიეთ საჭირო განყოფილება.
4. გახსენით ჩანართი**პარამეტრები (სპეციფიკური)**.
5. ცვლილებები**საზომი გამოკითხვის ინტერვალი**1 წმ-ზე.

🚀[სცადეთ საცავის დამატება ბმულზე](https://my.home-assistant.io/redirect/hacs_repository/?owner=LanKing\&repository=ha-smart-plug-multilevel-light\&category=integration). თუ თქვენი HA მხარს უჭერს ამ მეთოდს, დააწკაპუნეთ**დამატება**ფანჯარაში, რომელიც იხსნება და შემდეგ ღილაკს**ჩამოტვირთვა**ქვედა მარჯვენა კუთხეში. თუ ინსტალაცია წარმატებით დასრულდა, შეგიძლიათ გამოტოვოთ შემდგომი ნაბიჯები. გადადით პირდაპირ განყოფილებაზე[სწრაფი დაწყება](#getting-started).

#### 1. საცავის დამატება

მიუხედავად იმისა, რომ საცავი არ შედის სტანდარტული HACS დირექტორიაში, დაამატეთ იგი როგორც მორგებული:

3. დამატება:

```text
https://github.com/LanKing/ha-smart-plug-multilevel-light
```

4. აირჩიეთ ტიპი**ინტეგრაცია**და დააჭირეთ**დამატება**.

> საცავის დამატება მხოლოდ ინტეგრაციას ხდის HACS-ში. ინსტალაციისთვის საჭიროა ცალკე გახსნათ მისი ბარათი და დააჭიროთ**ჩამოტვირთვა**.

YAML რესურსის რეჟიმში, ბარათი უნდა დარეგისტრირდეს ხელით, როგორც ეს აღწერილია ქვემოთ.

## 🚀 სწრაფი დაწყება ინსტალაციის შემდეგ

### 🛠 კონფიგურაცია

1. გახსენი&#x10D7;**[პარამეტრები → მოწყობილობები და სერვისები → აქსესუარები](https://my.home-assistant.io/redirect/helpers/)**&#x10D3;ა დააჭირეთ**დამხმარე ობიექტის შექმნა**.

2. აირჩიეთ**Smart Plug მრავალ დონის განათება**.

3. აირჩიეთ ჭკვიანი შტეფსელი, რომელსაც ნათურა უკავშირდება. სიაში ნაჩვენებია მხოლოდ ის საშუალებები, სადაც Home Assistant ხედავს დენის სენსორს იმავე მოწყობილობაში.

4. შემდეგ ეტაპზე დააყენეთ ნათურის პარამეტრები:
   * **ნათურის სახელი (Light name)**— მაგალითად, შექმნილი სუბიექტის სახელი`FloorLamp`;
   * **Power sensor**- სოკეტის დენის სენსორი;

5. განყოფილებაში**ZUI003Z**დაამატეთ მინიმუმ ერთი სიკაშკაშის რეჟიმი დაწკაპუნებით**დამატება**.<br /> <img src="modes-edit.png" width="465"/>შეცვალეთ ნათურა მისი ფიზიკური ღილაკით, შეიყვანეთ რეჟიმის სახელი და დაიწყეთ**Test stable power**. სტაბილური მნიშვნელობის მიღების შემდეგ დააჭირეთ**მიმართეთ**.

6. პირველი რეჟიმის დამატების შემდეგ დაამატეთ დარჩენილი რეჟიმები ამ ნაბიჯების გამეორებით. თქვენ უნდა დაასრულოთ მსგავსი რამ:<br />
   <img src="modes-list.png" width="457"/>

7. შეინახეთ დამხმარე ობიექტი. Home Assistant შექმნის ახალ ერთეულს`light`, მაგალითად`light.FloorLamp`.

### 🧩 ლავლეისის ბარათი

1. გახსენით სასურველი პანელი, ჩართეთ რედაქტირების რეჟიმი და დააწკაპუნეთ**დაამატეთ ბარათი**.
2. აირჩიეთ**Smart Plug მრავალ დონის განათება**, მიუთითეთ შექმნილი ერთეული`light`და შეინახეთ ბარათი.

თუ ბარათი არ არის ხელმისაწვდომს შორის, შესაძლოა იყენებდეთ[Lovelace რესურსი YAML რეჟიმი](#yaml-lovelace-mode).

### 🎨 ვიზუალური ეფექტები

#### პარამეტრები ბარათში

გახსენით პანელი, სადაც ბარათი მდებარეობს, გადადით რედაქტირების რეჟიმში და დააწკაპუნეთ**რედაქტირება**სასურველ ბარათზე.

განყოფილების გახსნა**შიგთავსი (Content)**, ნახავთ ხელმისაწვდომ პარამეტრებს:

* **რეჟიმის სახელის ჩვენება (Show mode name)**— აჩვენებს ან მალავს მიმდინარე რეჟიმის სახელს: მაგალითად, Dim, Low, Medium ან High.
* **პროცენტის ჩვენება (Show percentage)**— აჩვენებს ან მალავს გამოთვლილ სიკაშკაშეს პროცენტულად.

განყოფილების გახსნა**ურთიერთქმედებები (Interactions)**, ნახავთ:

* **ხატულის ფონის ყოველთვის ჩვენება (Always show icon background)**— ინარჩუნებს მრგვალ ფონს ხატის გარშემო, მაშინაც კი, თუ მისთვის ცალკე მოქმედება გამორთულია.

> 🚫 სხვათა შორის, თუ თქვენც ჩემსავით იყენებთ ბარათის არასტანდარტულ ხატულას და გამორთვისას ვიზუალურად არ არის გადახაზული, გირჩევთ ჩემს სხვა დანამატს -[Mdi Off Fallback](https://github.com/LanKing/ha-mdi-off-fallback/blob/main/docs/README_ka.md), რომელიც წყვეტს ამ ესთეტიკურ პრობლემას.

#### სიკაშკაშის დამრგვალება 5%-მდე

გახსენი&#x10D7;**[პარამეტრები → მოწყობილობები და სერვისები → აქსესუარები](https://my.home-assistant.io/redirect/helpers/)**&#x10D8;პოვნეთ ადრე შექმნილი დამხმარე ობიექტი**Smart Plug მრავალ დონის განათება**და გახსენით მისი პარამეტრები. ჩართეთ ან გამორთეთ**Round brightness to 5% (may look nicer)**.

როდესაც პარამეტრი ჩართულია, გამოთვლილი პროცენტი მრგვალდება 5%-მდე, მაგალითად: 33% → 35%, 67% → 65%.

დამრგვალება მოქმედებს მხოლოდ ბარათის ჩვენებულ პროცენტზე და ვიზუალურ ინტენსივობაზე. ნათურის რეჟიმის განსაზღვრა და მოქმედება არ იცვლება. ნაგულისხმევად, დამრგვალება გამორთულია.

## 🧩 ლავლეისის ბარათი დეტალურად

ხელმისაწვდომი ვარიანტები:

| პარამეტრი | ტიპი | ნაგულისხმევი | აღწერა |
|---|---|---:|---|
| `entity` | string | საჭირო | ინტეგრაციის შედეგად შექმნილი ერთეული |
| `name` | string | ერთეულის სახელი | აჭარბებს ბარათზე გამოსახულ სახელს |
| `icon` | string | ერთეულის ხატულა | არღვევს ხატს |
| `show_mode` | boolean | `true` | აჩვენებს რეჟიმის სახელს |
| `show_percentage` | boolean | `true` | აჩვენებს სინთეზურ პროცენტს |
| `icon_tap_action` | action | `more-info` | დამატებითი მოქმედება ხატზე დაჭერისას |
| `always_show_icon_background` | boolean | `false` | ყოველთვის აჩვენებს წრიული ხატის ფონს, მაშინაც კი, როდესაც None არჩეულია icon_tap_action-ისთვის |

სრული მაგალითი:

```yaml
type: custom:smart-plug-multilevel-light-card
entity: light.floor_lamp
name: Торшер
icon: mdi:floor-lamp
show_mode: true
show_percentage: true
icon_tap_action:
  action: more-info
always_show_icon_background: false
```

### Lovelace რესურსი YAML რეჟიმი

> სავარაუდოდ, თქვენ არ გაქვთ ეს რეჟიმი ჩართული. თუ პრობლემა არ არის და ბარათი მუშაობს, გამოტოვეთ ეს ნაბიჯი.

თუ გაქვთ`configuration.yaml`აშკარად მითითებული:

```yaml
lovelace:
  resource_mode: yaml
```

Home Assistant არ აძლევს საშუალებას ინტეგრაციას ავტომატურად შეცვალოს რესურსების სია. ამ შემთხვევაში, დაამატეთ რესურსი ხელით:

```yaml
lovelace:
  resource_mode: yaml
  resources:
    - url: /api/smart_plug_multilevel_light/smart-plug-multilevel-light-card.js?v=0.10.9
      type: module
```

ცვლილების შემდეგ გადატვირთეთ Lovelace რესურსები ან გადატვირთეთ Home Assistant.

შეამოწმეთ დენის სენსორის მნიშვნელობა. ვირტუალური ნათურა ჩაითვლება გამორთული, როდესაც`0 W`; როდესაც დადებითია, ის უნდა განისაზღვროს როგორც`on`.

<summary><b>❓ნათურა ნაჩვენებია როგორც ჩართული, როდესაც ის ფიზიკურად გამორთულია</b></summary>
<br />

შეამოწმეთ, რომ არჩეული დენის სენსორი ნამდვილად აჩვენებს`0 W`, როცა ნათურა გამორთულია საკუთარი ღილაკით.

<details>
<summary><b>❓გამოვლენილია არასწორი რეჟიმი</b></summary>
<br />

შეამოწმეთ**🐞 Last measures**პარამეტრებში და ატრიბუტებში`power_history`,`power_history_modes`,`power_sample_interval_seconds`და`selected_power_mode`.`power_history`აჩვენებს ბოლო ჩაწერილი სიმძლავრის მნიშვნელობებს,`power_history_modes`— რეჟიმი თითოეული მათგანისთვის კონფიგურირებული ზღვრების მიხედვით,`power_sample_interval_seconds`არის პერიოდული ფიქსაციის ინტერვალი და`selected_power_mode`— მიმდინარე დადასტურებული რეჟიმი.

</details>

<details>
<summary><b>❓რეჟიმის ცვლილებები დაუყოვნებლივ არ არის ნაჩვენები</b></summary>
<br />

ეს მოსალოდნელი ქცევაა. ელექტროენერგიის მოკლევადიანი რყევების თავიდან ასაცილებლად, რომ არ გამოიწვიოს ყალბი გადართვა, ინტეგრაცია ცვლის რეჟიმს მხოლოდ რამდენიმე თანმიმდევრული წაკითხვის შემდეგ, რაც შეესაბამება იმავე ახალ რეჟიმს.

წაკითხვის საჭირო რაოდენობა დგინდება პარამეტრით**Consecutive readings to switch**და ნაგულისხმევი`5`. პერიოდული გაზომვები ხორციელდება წამში ერთხელ და სენსორის მდგომარეობის ცვლილებები დაუყოვნებლივ მუშავდება. თუ ტესტირებისას მნიშვნელობა შეესაბამება სხვა რეჟიმს, ათვლა ისევ იწყება.

დადასტურებამდე, ინტეგრაცია ინარჩუნებს წინა რეჟიმს. ამის წყალობით, ბარათი არ იცვლება რეჟიმებს შორის შუალედური მნიშვნელობების გამო, რაც ხდება ნათურის გადართვის, მისი სიმძლავრის სტაბილიზაციის ან სენსორის წაკითხვის მცირე რყევების დროს.

წაკითხვის რაოდენობის შემცირება აჩქარებს ახალი რეჟიმის ჩვენებას, მაგრამ ამოცნობას უფრო მგრძნობიარეს ხდის დენის რყევების მიმართ.
