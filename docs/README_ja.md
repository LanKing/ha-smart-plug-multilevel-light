# 🔌 スマートプラグマルチレベルライト

![Пример режимов на карточке](ha-smart-plug-multilevel-light-card-modes-v4.png)

**✨ 特徴と特徴:**

* ネイティブのホーム アシスタント エンティティを作成します`light`自動化、スクリプト、標準の HA インターフェイスとの互換性。
* 消灯方法に関係なく、ランプが正しく点灯します。スマート ソケットを通じて電源がオフになっている場合は、単にオンになります。ソケットがオンのときにランプが独自のボタンでオフになった場合、電源がオフになってから再びオンになるというサイクルが実行されます。
* 実際に測定された安定した電力に基づいて、ランプの現在の動作モードを自動的に決定します。
* これには、ユーザーがランプでサポートされているモードに順番に名前を付けるシンプルなコンフィギュレーターがあり、システムは各モードでの安定した電力を決定することによって学習します。
* 最初の設定中に、電力はリアルタイムで読み取られます。ユーザーはライトを次のモードに切り替えて学習ボタンを押すだけです。
* 不安定な電力測定値をフィルタリングして除去し、電力が 1 つのモード内で「ジャンプ」したとき (さらには次のモードと一致したとき)、カード上のインジケーターが無秩序に変化するのを防ぎます。
* 任意の数のモードをサポートします。
* このカードは、標準のホーム アシスタント タイル カードの上に構築されており、そのジオメトリ、背景、ホバー効果、サイズ、タイポグラフィー、標準アクションが維持されています。
* カードでは、現在の明るさが色の強度によって視覚的にエンコードされます。
* 明るさを最大パワーに対して線形に計算します。パーセンテージをより正確に表示するために、計算された明るさの 5% への四捨五入を有効にすることができます。
* 表示されるパラメータとカードの外観を柔軟にカスタマイズできます。
* 選択したスマート プラグに関連する電力センサーのみを選択できます。
* さまざまなモデルのランプやソケットで正しく動作するように、非通電サイクルの遅延を調整できます。
* ランプがオフであるとみなされる電力しきい値を設定できます。
* このインターフェイスは、64 の Home Assistant ロケールにローカライズされています。

## 🗜 アイロンの準備

必要なものは次のとおりです。

1. HA に電力制御 (スイッチ) と電力測定 (device\_class: power のセンサー) を提供するスマート ソケット。両方のエンティティが同じデバイスに属し、有効になっている必要があります。
2. プラグを差し込むと自動的に点灯し、複数の明るさ設定があり、完全に楽しむことができる愚かなライトです。

> ソケットを使用しました[Tuya TS011F (ギリエケース入り)](https://www.zigbee2mqtt.io/devices/TS011F_plug_3.html)。実験の初めに、Girier シリーズのソケットは不正確な測定のために適合しませんでしたが、このモデルは、Girier のケースにもありましたが、適合しました。

### 👨‍🔬 コンセントに適用した重要な設定:

> 私のソケットは読み取り値を HA に自動的に報告せず、指定された間隔でのポーリングのみを許可します。デフォルトでは 60 秒でした。この間隔を 1 秒に設定しないと、モード切り替え表示が表示されるまでに非常に長い時間がかかります。

この説明は、Z2M 経由で接続されたソケットの所有者にのみ関係します。他のユーザーは、設定内でリフレッシュ レートを調整する必要があります。

1. 開ける**ホームアシスタント → Zigbee2MQTT**。 Zigbee2MQTTがサイドメニューにない場合は、開きます**設定 → アプリケーション → Zigbee2MQTT → Web インターフェイスを開く**.
2. セクションに移動**デバイス**.
3. 必要なコンセントを選択します。
4. タブを開く**設定（具体的な）**.
5. 変化**測定ポーリング間隔**1秒で。

## 📦 インストール

### 🛍 HACS経由のインストール

ℹ️[HACS とは何ですか?また、そのインストール方法は何ですか?](https://github.com/LanKing/ha-tools/blob/main/appendix-what-is-hacs/docs/README_ja.md)

🚀[リンクにリポジトリを追加してみてください](https://my.home-assistant.io/redirect/hacs_repository/?owner=LanKing\&repository=ha-smart-plug-multilevel-light\&category=integration)。 HA がこの方法をサポートしている場合は、**追加**開いたウィンドウで、ボタンをクリックします。**ダウンロード**右下隅にあります。インストールが正常に完了した場合は、以降の手順をスキップできます。セクションに直接スキップ[クイックスタート](#getting-started).

#### 1. リポジトリの追加

リポジトリは標準の HACS ディレクトリには含まれていませんが、カスタム ディレクトリとして追加します。

1. 開ける**HACS → 統合**.
2. 右上隅のメニューを開いて選択します**カスタムリポジトリ**.
3. 追加：

```text
https://github.com/LanKing/ha-smart-plug-multilevel-light
```

4. タイプを選択してください**統合**そして押します**追加**.

> リポジトリを追加すると、HACS で統合が利用可能になるだけです。インストールするには、カードを個別に開き、クリックする必要があります。**ダウンロード**.

#### 2. インテグレーションのインストール

1. HACS で検索:`Smart Plug Multi-Level Light`.
2. 統合を開いてクリックします**ダウンロード**.
3. インストール後、Home Assistant を完全に再起動します。

### 🧑‍💻 HACS を使用しないインストール

1. リポジトリ ページで、**コード→ZIPをダウンロード**.
2. アーカイブを解凍します。
3. フォルダーをコピーします。

```text
custom_components/smart_plug_multilevel_light
```

ホーム アシスタント設定ディレクトリへ:

```text
/config/custom_components/smart_plug_multilevel_light
```

最終的なファイルパス`manifest.json`次のようになります:

```text
/config/custom_components/smart_plug_multilevel_light/manifest.json
```

### 🎨 視覚効果

#### カード内の設定

カードが配置されているパネルを開き、編集モードに移動して、**編集**希望のカードに。

セクションを開く**内容 (Content)**を選択すると、利用可能な設定が表示されます。

* **モード名を表示 (Show mode name)**— 現在のモードの名前を表示または非表示にします。たとえば、Dim、Low、Medium、High などです。
* **パーセントを表示 (Show percentage)**— 計算された明るさをパーセンテージとして表示または非表示にします。

セクションを開く**操作 (Interactions)**、次のように表示されます。

* **アイコン背景を常に表示 (Always show icon background)**— アイコンの別のアクションが無効になっている場合でも、アイコンの周囲の丸い背景が保持されます。

> 🚫 ちなみに、私と同じように、非標準のカードアイコンを使用していて、オフにしても視覚的に取り消し線が表示されない場合は、私の他のプラグインをお勧めします -[Mdi オフ フォールバック](https://github.com/LanKing/ha-mdi-off-fallback/blob/main/docs/README_ja.md)、この美的問題を解決します。

#### 明るさは5%未満四捨五入

開け&#x308B;**[設定 → デバイスとサービス → アクセサリ](https://my.home-assistant.io/redirect/helpers/)**、前に作成したヘルパー オブジェクトを見つけます。**スマートプラグマルチレベルライト**そしてその設定を開きます。オンまたはオフにする**Round brightness to 5% (may look nicer)**.

この設定が有効な場合、計算されたパーセンテージは最も近い 5% に四捨五入されます (例: 33% → 35%、67% → 65%)。

四捨五入は、表示されるパーセンテージとカードの視覚的な強度にのみ影響します。モード定義とランプの動作は変わりません。デフォルトでは、丸めは無効になっています。

## 🧩 ラブレスカードの詳細

利用可能なオプション:

| パラメータ | 種類 | デフォルト | 説明 |
|---|---|---:|---|
| `entity` | string | 必須 | 統合によって作成されたエンティティ |
| `name` | string | エンティティ名 | カードに表示されている名前を上書きします |
| `icon` | string | エンティティアイコン | アイコンをオーバーライドします |
| `show_mode` | boolean | `true` | モード名を示します |
| `show_percentage` | boolean | `true` | 合成の割合を示します |
| `icon_tap_action` | action | `more-info` | アイコンをタップしたときの追加アクション |
| `always_show_icon_background` | boolean | `false` | icon_tap_action に None が選択されている場合でも、常に円形のアイコンの背景が表示されます。 |

完全な例:

```yaml
type: custom:smart-plug-multilevel-light-card
entity: light.floor_lamp
name: Торшер
icon: mdi:floor-lamp
show_mode: true
show_percentage: true
icon_tap_action:
  action: more-info
always_show_icon_background: false
```

<a id="yaml-lovelace-mode"></a>

### Lovelace リソースの YAML モード

> おそらく、このモードが有効になっていません。問題がなくカードが動作する場合は、この手順をスキップしてください。

持っている場合`configuration.yaml`明示的に設定:

```yaml
lovelace:
  resource_mode: yaml
```

ホーム アシスタントでは、統合によってリソースのリストを自動的に変更することはできません。この場合、リソースを手動で追加します。

```yaml
lovelace:
  resource_mode: yaml
  resources:
    - url: /api/smart_plug_multilevel_light/smart-plug-multilevel-light-card.js?v=0.10.9
      type: module
```

変更後、Lovelace リソースを再起動するか、Home Assistant を再起動します。

## 🧯 トラブルシューティング

<details>
<summary><b>❓統合がヘルパー リストに表示されない</b></summary>
<br />

**考えられる原因:**&#x30D1;スが間違っているか、Home Assistant が再起動されていません。

/config/custom_components/smart_plug_multilevel_light/manifest.json

次に、Home Assistant を完全に再起動し、ログでエラーを確認します。`smart_plug_multilevel_light`.

</details>

<details>
<summary><b>❓プラグリストが空です</b></summary>
<br />

統合ではオブジェクトのみが表示されます`switch`付属のセンサーも提供するデバイスに関連付けられています。`device_class: power`.

チェックイ&#x30F3;**[設定 → デバイスとサービス → オブジェクト](https://my.home-assistant.io/redirect/entities/)**:

* 彼らは所属していますか`switch`1 つのデバイス用のパワーセンサー?
* パワーセンサーはONになっていますか？
* 正しく指定されていますか?`device_class`?
* 数値的な状態はありますか?

<hr />
</details>

<details>
<summary><b>❓パワーセンサーが見つからないというメッセージが表示されて作成が停止する</b></summary>
<br />

コンセントを選択した後、統合は電力センサーの存在を再チェックします。このエラーは、センサーが取り外されたり、無効になったり、別のデバイスに移動されたり、センサーが存在しなくなったりした場合に発生します。`device_class: power`.

<hr />
</details>

<details>
<summary><b>❓プラグがオンの場合、ランプはオフと表示されます</b></summary>
<br />

パワーセンサーの値を確認してください。仮想ランプは次の場合にオフになっているとみなされます。`0 W`;正の場合、次のように定義する必要があります。`on`.

<hr />
</details>

<details>
<summary><b>❓ランプは物理的にオフでもオンとして表示されます</b></summary>
<br />

選択したパワーセンサーが実際に表示されていることを確認します`0 W`、ランプが独自のボタンによって消灯されるとき。

<hr />
</details>

<details>
<summary><b>❓間違ったモードが検出されました</b></summary>
<br />

チェック**🐞 Last measures**設定と属性で`power_history`,`power_history_modes`,`power_sample_interval_seconds`そして`selected_power_mode`.`power_history`最後に記録された電力値を示します。`power_history_modes`— 設定されたしきい値に応じたそれぞれのモード、`power_sample_interval_seconds`は定期的な注視の間隔であり、`selected_power_mode`— 現在確認されているモード。

<hr />
</details>

<details>
<summary><b>❓モード変更はすぐには表示されません</b></summary>
<br />

これは予期された動作です。短期間の電力変動によって誤ったスイッチングが発生するのを防ぐため、積分では、いくつかの連続した読み取り値が同じ新しいモードに対応した後でのみモードが変更されます。

必要な読み取り数はパラメータによって設定されます。**Consecutive readings to switch**そしてデフォルトは`5`。定期的な測定は 1 秒に 1 回実行され、センサー状態の変化は即座に処理されます。テスト中に値が別のモードに対応する場合、カウントダウンが再び開始されます。

確認されるまで、統合は以前のモードを維持します。このおかげで、ランプの切り替え時に発生する中間値、電力の安定化、またはセンサーの読み取り値の小さな変動によってカードがモード間で切り替わることはありません。

読み取り数を減らすと、新しいモードの表示が高速化されますが、検出は電力変動に対してより敏感になります。

<hr />
</details>

<details>
<summary><b>❓カードがリストに表示されない</b></summary>
<br />

自動登録は、少なくとも 1 つの構成済みヘルパー オブジェクトをロードした後、かつリソース モードでのみ行われます。`storage`。統合のインストール方法 (HACS 経由または手動) は、これに影響しません。

チェッ&#x30AF;**[設定 → パネル → ⋮ → リソース](https://my.home-assistant.io/redirect/lovelace_resources/)**。 URL がそこにあるはずです。

```text
/api/smart_plug_multilevel_light/smart-plug-multilevel-light-card.js?v=0.10.9
```

YAMLモードの場合[リソースを手動で追加する](#yaml-lovelace-mode).

<hr />
</details>
